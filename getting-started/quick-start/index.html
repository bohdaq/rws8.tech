Quick Start

Pick the path that matches your goal. Each ends with a working server you can hit with curl.

Path 1 — Static file server (zero code)

Section titled “Path 1 — Static file server (zero code)”

Install the binary and point it at a directory. No config file, no code.

rws serves every file under the current directory, handles range requests, sets ETags, negotiates gzip, and returns 404 for missing files — all with no configuration. A directory with no index.html renders a directory listing page instead of 404 — try mkdir www/uploads && touch www/uploads/report.pdf && curl http://localhost:7878/uploads/.

HTTPS in one flag

Path 3 — Config-driven proxy (no code)

Section titled “Path 3 — Config-driven proxy (no code)”

Drop an rws.config.toml next to the rws binary and it becomes a reverse proxy and load balancer. No code required.

Minimal config

Section titled “Minimal config”

What the config does

Section titled “What the config does”
  • [[upstream]] declares a named backend pool with health checking. Dead backends are removed automatically; they re-enter rotation once they pass healthy_threshold consecutive checks.
  • [[route]] rules are evaluated top-to-bottom, first match wins. A path ending in * is a prefix match (/api/* matches /api/users); without it the path must match exactly. Requests no route matches fall through to the static-file server.
  • type = "proxy" forwards the request to the named upstream. type = "respond" returns a fixed response.

Add middleware per route

Rate limiting, Bearer auth, and request rewriting can all be added per-route inside the config file — no code change needed. See the Proxy & Gateway documentation for the full schema.

HTTPS in front of the proxy

Add an [acme] section (Path 4) and rws gets Let’s Encrypt certificates for the proxy itself. To use your own certificates instead, set tls_cert_file / tls_key_file; per-domain certificates go in [[virtual_host]] blocks.

Path 4 — Automatic HTTPS (no code)

Section titled “Path 4 — Automatic HTTPS (no code)”

On a server whose DNS points at it, with ports 80 and 443 reachable:

On first start rws requests a certificate from Let’s Encrypt (stored as cert.pem / key.pem), then serves HTTPS with HTTP/2 and HTTP/3 and redirects HTTP to HTTPS. Renewal runs in the background. Try it against the Let’s Encrypt staging CA first with staging = true — see Automatic HTTPS.
