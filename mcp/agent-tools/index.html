Build agent tools on your app

An app built on rws can answer AI agents with the same functions its REST API calls. app.mcp(name, version) puts an MCP endpoint at /mcp in front of the app; each domain function becomes a typed tool whose schemas come from its Rust types; everything else still reaches the app. The runnable version is examples/mcp_inventory.rs.

One domain, two front doors

Section titled “One domain, two front doors”

Keep the logic in plain functions over plain types, and let the REST handlers and the tools both call them:

  • The doc comments on the types are what the model reads about each argument; write them for it.
  • A domain error (only 1 of TEE-02 on hand) returns as an isError result the model can act on, not a protocol failure.
  • Mark tools that only read with read_only_hint, so clients that ask before acting ask only for the ones that change something.

Who is calling

Section titled “Who is calling”

/mcp needs a token; the REST routes keep their own rules.

  • One shared token: .require_bearer(token).
  • Your identity provider: .require_oauth(OidcProvider::discover(issuer)?, audience). rws checks the token’s signature, issuer, expiry and audience, serves /.well-known/oauth-protected-resource so clients can find the provider, and hands the verified claims to every tool as ctx.auth_claims — the example records the caller’s e-mail on each stock change. The example takes the issuer and audience from MCP_OAUTH_ISSUER and MCP_OAUTH_AUDIENCE. See Auth.

Live updates

Section titled “Live updates”

A resource plus notify_resource_updated lets a client keep a view current. The example serves inventory://items and, whenever the stock changes — through a tool or through the REST API — tells every session subscribed to it:

A client holding GET /mcp open (SSE) and subscribed with resources/subscribe receives {"method":"notifications/resources/updated","params":{"uri":"inventory://items"}} and reads the resource again.

Testing

Section titled “Testing”

TestClient drives the whole stack, auth included, without a socket — the example’s tests call tools over /mcp, then check the change through the REST route:

cargo test --example mcp_inventory --features "macros serde sso openapi" runs them.
